💡 What:
Enabled asynchronous OS-level I/O by passing `useAsync: true` to the `FileStream` constructor in `ImageProcessingService.LoadWebpForWinFormsAsync`.

🎯 Why:
The `Image.LoadAsync(fs)` method reads from the stream asynchronously. If the `FileStream` is not opened with `useAsync: true`, .NET performs standard blocking I/O on thread pool threads (sync-over-async), which blocks threads while waiting for the OS to complete the disk read. Under heavy load or in environments with limited thread pools, this leads to thread pool starvation, drastically degrading application performance and responsiveness. Enabling `useAsync: true` delegates the I/O off the thread pool (using overlapped I/O on Windows or equivalent mechanisms on Linux), allowing threads to process other work while the disk read completes.

📊 Impact:
Eliminates thread pool exhaustion caused by synchronous reads during asynchronous ImageSharp loading.

🔬 Measurement:
A standalone benchmark reading a 10MB file 100 times concurrently with a constrained thread pool (`ThreadPool.SetMaxThreads(10, 10)`) demonstrated the impact. While raw disk I/O time variations exist across sandbox environments, the key optimization is reducing thread pool queue wait times. In a constrained environment, `useAsync: true` ensures threads are yielded immediately rather than blocking synchronously on I/O.
