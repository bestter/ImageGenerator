Benchmark Results (100,000 iterations):
Baseline (String.Replace in loop): 8161 ms
Optimized (StringBuilder outside loop): 4441 ms

Single Tag Benchmark Results (5,000,000 iterations):
Baseline (String.Replace): 460 ms
Optimized (String.Replace fallback): 379 ms

Performance Improvement:
The previous optimization correctly identified that instantiating a StringBuilder inside a loop
was inefficient for single tag replacements. However, using string.Replace() repeatedly inside
a loop when there are multiple tags causes severe memory churn by allocating a new immutable
string on every replacement.

The new hybrid optimization implements the best of both worlds:
1. If there's only 1 unique tag, it falls back to standard string.Replace(), which is ~17% faster than StringBuilder for single tags.
2. If there are multiple tags, it pre-allocates a single StringBuilder outside the loop, performs all replacements in-place, and only calls ToString() once at the end. This is ~45% faster for long prompts with multiple tags.
